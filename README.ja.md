# herdr-jira-board

Jira のボードをカンバン TUI として [herdr](https://herdr.dev) 内に表示し、
カードから [Claude Code](https://claude.com/claude-code) セッションを起動できる
herdr プラグイン。セッションの状態バッジが看板上でライブ更新されます。

English version: [README.md](README.md)

![demo](demo/demo.gif)

## 機能

- JQL で取得した課題をステータスカテゴリ3列 (To Do / In Progress / Done) で表示
  — カスタムワークフローのプロジェクトが混在しても破綻しません。
  デフォルトでは「自分の未完了課題 + 直近7日以内に更新された完了課題」を表示し、
  古い完了カードは自動的に消えます（設定の `jql` で変更可能）
- カードは `←` `→` キーまたはドラッグ&ドロップで移動し、`Enter` で確定して
  Jira のトランジションを実行（候補が複数のときは選択ポップアップ）。
  仮移動は溜められるので、複数のカードを1枚ずつ動かしてまとめて確定できます。
  `t` で同一列内のもの（進行中 → 社内レビュー中 など）も含む全トランジション
  からステータスを変更できます
- カード上で `Enter` すると、その課題を担当する Claude Code セッションを
  新しい herdr タブに起動（`JIRA_ISSUE_KEY` と、サマリ・ステータス・期限・
  説明文・URL を含む初期プロンプトを注入）。
  ボードの相棒セッション（`c`）の記録を引き継ぐので、既に話していた内容から
  始められます（[詳細](#相棒セッション)）
- カードを選ぶと、その課題を担当しているセッションの**最後の返答**をボード下部に
  プレビュー表示します。記録（トランスクリプト）から読むだけなので、セッションに
  何も送らず、頭の中で状態を覚えておかなくて済みます（[詳細](#セッションのプレビュー)）。
  セッションが既にあるカードで `Enter` すると、そのタブへ移動します。
  列だけを見たいときは `p` でプレビューを消せます（起動時の状態は設定 `preview`）
- 複数ステータスが混在する列（主に In Progress）は、ステータスごとに区切り
  ラベルを入れてカードをグループ表示。並び順は設定 `status_order` で指定可能
- **フェーズラベル**（`l`）で、専用のワークフローステータスにするほどではない
  段階（たとえば「リリース後の効果を確認中」）を示せます。Jira のラベルはサイト
  全体で共有されるので、ワークフローに手を入れず1つの名前が全プロジェクトで
  使えます。ラベルの付いたカードはラベル名を表示し、同じステータス内で先頭に
  並びます（[詳細](#フェーズラベル)）
- **盤面優先度**（`board_priority`）で、親エピックと Jira 優先度から成るルール
  リストでカードに順位を付けられます — 「STのブロッカー > UATのブロッカー >
  それ以外のST」のような並びが書けます。順位の付いたカードは `P1`/`P2`/… を
  表示し、ステータスグループの先頭に並びます（[詳細](#盤面優先度)）
- **ステータス連動ラベル**（`status_labels`）で、ボードから実行した遷移が特定の
  ステータスに着地したときのラベルの付け外しを自動化できます — レビューに入ったら
  「要効果確認」を付ける、完了に移ったらボードの管理ラベルを外す、など
  （[詳細](#ステータス連動ラベル)）
- `herdr agent list` を5秒ごとにポーリングし、カードにセッション状態バッジ
  (working / blocked / idle / done) を表示
- カードに作成日と期限を表示（期限切れは赤、3日以内は黄）
- `bin/jira-board --dump` で同じ盤面を TUI なしのテキスト（または JSON）で出力。
  Claude Code から読ませるスキルも同梱 — [Claude からボードを読む](#claude-からボードを読む)
- タブ整理アクション（他のタブを閉じる / 右側のタブを閉じる）付き
- UI は英語 / 日本語対応 — システムロケールに追従し、設定で上書きも可能

## 必要なもの

- herdr >= 0.7.5 (macOS / Linux)
- Python 3.11+ **または** [uv](https://docs.astral.sh/uv/)
- Jira Cloud アカウントと API トークン

## インストール

```
herdr plugin install kiitosu/herdr-jira-board
```

これだけです。インストール時に Python 環境を自動で準備します
（uv があれば uv を、なければ専用の仮想環境を使います）。

## 設定

1. https://id.atlassian.com/manage-profile/security/api-tokens で API トークンを
   作成（「スコープ付き」ではなくクラシックな「API トークンを作成」を選択）。
2. [config.toml.example](config.toml.example) をプラグインの設定ディレクトリに
   コピーして編集:

```
cp config.toml.example "$(herdr plugin config-dir jira-board)/config.toml"
```

最小構成:

```toml
site = "https://your-site.atlassian.net"
email = "you@example.com"
api_token = "<API トークン>"
```

すべてのオプション（`api_token_cmd`, `jql`, `exclude_statuses`, `status_order`,
`phase_labels`, `board_priority`, `status_labels`, `language`, `preview`,
`[project_dirs]`）は
`config.toml.example` のコメントを参照してください。

## 使い方

herdr 内で看板を開く:

```
herdr plugin pane open --plugin jira-board --entrypoint board
```

`~/.config/herdr/config.toml` にキーバインドを登録しておくと便利です:

```toml
[[keys.command]]
key = "prefix+k"
type = "plugin_action"
command = "jira-board.open-board"
description = "看板表示"

[[keys.command]]
key = "prefix+x"
type = "plugin_action"
command = "jira-board.close-right-tabs"
description = "右のタブを閉じる"

[[keys.command]]
key = "prefix+shift+x"
type = "plugin_action"
command = "jira-board.close-other-tabs"
description = "他のタブを閉じる"
```

### キー操作

| キー | 動作 |
| --- | --- |
| `↑` `↓` | 前 / 次のカードへフォーカス |
| `←` `→` | 隣の列へ仮移動 |
| `Enter` | 仮移動を全て確定、または Claude セッション起動（起動済みならそのタブへ移動） |
| `Esc` | 仮移動を全て取消 / 選択解除 |
| `r` | 看板を更新 |
| `o` | 課題をブラウザで開く |
| `t` | カードのステータスを変更（同一列内も含む全トランジションから選択） |
| `l` | カードのフェーズラベルを編集（space で選択、enter で反映） |
| `c` | 相棒セッションを隣に開く / そこへ移動 |
| `p` | 返答プレビューの表示 / 非表示 |
| `q` | 終了 |

マウスでカードを列間ドラッグすることもできます（同様に仮移動 → `Enter` で確定）。

仮移動はカードごとに溜まります。好きな枚数のカードを（それぞれ別の列へ）仮移動して
おき、`Enter` で順番にまとめて実行できます。トランジション候補が複数のカードは
順番が来たときに選択ポップアップが出ます。失敗したカードだけ元の列に戻り、
残りはそのまま実行されます。`←` `→` で元の列に戻せば、そのカードだけ確定対象から
外れます。

### フェーズラベル

ワークフローのステータスにするほどではない段階もあります。「MR はマージ済み、
あとは実際に効果があったかを見る」がその一つです。そのためにステータスを追加すると
各プロジェクトのワークフローを編集することになり、それは Jira 管理者の仕事です。
一方 Jira のラベルはサイト全体で共有されるので、1つの名前が全プロジェクトをカバーし、
誰でも付けられます。

ボードに管理させたいラベルを宣言します:

```toml
[[phase_labels]]
label = "jb_verifying"     # Jira 上のラベル名
display = "verifying"      # カードに表示する名前

[[phase_labels]]
label = "jb_waiting"
display = "waiting"
```

カード上で `l` を押すと、宣言したラベルの選択ポップアップが開きます。そのカードが
既に持っているラベルには最初からチェックが付いています。`space` でチェックを付け外し、
`enter` で全部まとめて反映、`esc` で破棄します。変わるのは自分で編集したラベルだけで、
他の人が課題に付けたラベルはそのまま残ります。何個変更しても Jira への通信は1回です。

フェーズラベルの付いたカードは、宣言した順に、同じステータスグループの先頭へ並び、
ステータスの隣に `display` を表示します。これは `status_order` とは独立です。
ステータスのグループ自体は動かず、ラベルは1つのグループ内でのカードの並び順だけを
変えます。

ラベル名には接頭辞を付けてください（上の例の `jb_…`）。Jira のラベルはサイト上の
他の全プロジェクトと共有されるため、素の `verifying` は誰の入力補完にも出てきます。
カードに出るのは `display` だけなので、接頭辞が表示幅を食うことはありません。
表示名を分ける必要がなければ、文字列だけの指定（`phase_labels = ["verifying"]`）も
使えます。

### 盤面優先度

「次にどれを取るか」は単一のフィールドでは決まらないことが多いです。
「STエピックのブロッカーが最優先、次に UAT のブロッカー、その次は優先度によらず
ST の残り」のような並びは、エピック→優先度の単純な辞書式では表現できません。
`board_priority` は**上から順に評価するルールリスト**で、カードは最初にマッチした
ルールの位置を順位として持ちます:

```toml
[[board_priority]]
epic = "STテスト"
priority = "ブロッカー"

[[board_priority]]
epic = "UATテスト"
priority = "ブロッカー"

[[board_priority]]
epic = "STテスト"          # 優先度によらず、STの残り全部
```

`epic` は親エピックの指定で、キーの完全一致か**名前の部分一致**で照合します
（`"STテスト"` はエピック「STテスト（不具合起票）」にマッチ）。
省略するとどのエピックにもマッチします。`priority` は Jira の優先度名で、
省略すると「優先度によらず」です。両方省略したルールは全カードを飲み込むだけ
なので無視されます。

順位の付いたカードにはマーカー（位置に応じた `P1`/`P2`/…、または `display` で
指定した表示名）が付き、上位2段は赤・次の2段は黄で表示されます（期限と同じ
配色の流儀）。同一ステータスグループ内では順位でソートされ、フェーズラベルより
先に効きます（順位は「どれから取るか」の答えなので先頭）。どのルールにも
マッチしないカードは、順位付きの後ろに従来の並びのまま置かれます。
`--dump` はマーカーを表示し、`--dump --json` は課題ごとに `priority`・`epic`・
`board_priority` を含みます。

### ステータス連動ラベル

「当然そうなるべき」ラベル操作は自動化できます。レビューに入ったチケットには
「後で効果を確認する」ラベルが付くべきですし、完了でボードを離れるカードは
ボードの管理用ラベルを持ち続けるべきではありません。`status_labels` にその変更を
宣言しておくと、ボードから実行した遷移が該当ステータスに着地したときに適用されます:

```toml
[[status_labels]]
status = "レビュー中"
add = ["jb_要効果確認"]

[[status_labels]]
status = "完了"
remove_except = ["jb_要効果確認"]
```

`add` はラベルを付けます。`remove` は列挙したラベルを外します。`remove_except` は
「以外」の形で、**設定ファイルに登場するラベル**（`phase_labels` の宣言と
`status_labels` の各ルールに書かれたもの）のうち、列挙した以外の全部を外します。
他の人が課題に付けたラベルには決して触れません。ステータス名は大文字小文字を
無視して比較され、1課題分の変更は1リクエストで適用されます。対象のラベルは
フェーズラベルでなくても構いません（カードに表示されるのはフェーズラベルだけです）。

矛盾した書き方は中途半端に適用せず、ルールごと無視します: `remove` と
`remove_except` の併記、および同じラベルの add と remove の併記です。また、
同一ステータスのルール群を通して、add されるラベルが外されることはありません。

ルールが発火するのは**ボードから実行した遷移**（`←` `→` + `Enter`、`t`）だけです。
Jira の Web UI でステータスを変えた場合は発火しません。どこから変えても必ず
効かせたいルールは、Jira 本体の自動化（Automation）の出番です。

### 相棒セッション

`c` でボードの隣のペインに Claude Code セッションを開きます。相談しながら考える
ためのセッションで、実装はカードから起動する個別セッションが担当します。もう一度
`c` を押すとそのペインに移動します。

ボードは相棒の Claude セッションIDを記録するので、ペイン（やボード自身）を閉じた
後でも `c` で `claude --resume <session-id>` により**同じ会話が復帰**します。
Claude 側にもう無いセッション（何も話さないまま閉じた場合など）は、新規セッション
に差し替わります。

### 起動するセッションへの引き継ぎ

`Enter` でセッションを起動するとき、ボードは紐づいているセッション ——
相棒セッション（どのタブに居ても対象）と、ボードと同じ herdr タブにいる他の
Claude ペイン（`HERDR_TAB_ID` と `herdr pane list` で特定）—— の記録
（トランスクリプト）のパスを初期プロンプトに追記します。新しいセッションには
「課題キーで grep して該当部分だけ読め」と伝えるので、既に詰めた内容を打ち直さずに
引き継げます。

トランスクリプトはセッションIDで
`${CLAUDE_CONFIG_DIR:-~/.claude}/projects/*/<session-id>.jsonl` から探します。
まだ記録の無いセッション（何も話していないもの）は対象外で、紐づくセッションが
無ければ初期プロンプトは従来どおりです。

### セッションのプレビュー

セッションのあるカードにフォーカスすると、そのセッションの**最後の返答**を
ボード下部にプレビュー表示します。並行している課題の状態を頭の中に置いておかず、
カードに戻ってくれば今どこまで進んでいるかが読める、という機能です。

返答は記録（`${CLAUDE_CONFIG_DIR:-~/.claude}/projects/*/<session-id>.jsonl`）から
直接読みます。セッションには**何も送らない**ので、確認のたびにターンを消費したり、
作業中のセッションに割り込んだりすることはありません。状態バッジと同じ5秒間隔で
更新されるため、作業中のセッションの最新の報告も追いかけられます。

セッションが無いカード、またはまだ返答の無いセッションではプレビューは出ません。

`p` でプレビューを消して列だけの表示にでき、もう一度押すと戻ります。設定に
`preview = false` を書けば、最初から非表示で起動します。

## Claude からボードを読む

`--dump` は TUI を開かず、看板と同じ設定・JQL・除外・列分類で盤面をテキスト出力します。

```
bin/jira-board --dump          # テキスト
bin/jira-board --dump --json   # 機械可読
```

Jira MCP でボード全件を取ると各課題の description まで返ってきて応答が肥大するため、
Claude Code セッションからボードを把握する手段としてはこちらを使います。

これを呼ぶ Claude Code スキルを `skills/jira-board` に同梱しています。既定では
インストールされません。環境変数を付けると `~/.claude/skills` へコピーします
（`CLAUDE_CONFIG_DIR` があればそちらを優先）。

```
HERDR_JIRA_BOARD_INSTALL_SKILL=1 herdr plugin install kiitosu/herdr-jira-board
# インストール済みならビルド手順だけ再実行:
HERDR_JIRA_BOARD_INSTALL_SKILL=1 bin/setup
```

以後 Claude は「ボードの状況を確認して」等で自動的にこのスキルを使い、dump を実行します。
書き込むのは `~/.claude/skills/jira-board` だけで、そこに本プラグイン以外が作った
ディレクトリがある場合は何もしません。

コピーされたスキルは実行時にプラグインの場所を自力で解決するため、プラグイン更新後も
そのまま動きます。プラグインを通常と異なる場所に置いている場合は
`HERDR_JIRA_BOARD_ROOT` で明示してください。

## 開発

```
git clone https://github.com/kiitosu/herdr-jira-board
herdr plugin link herdr-jira-board   # 編集が即時反映されます
```

TUI を開かず設定だけ確認: `bin/jira-board --check`  
TUI を開かず盤面を確認: `bin/jira-board --dump`

テスト実行:

```
uv run --with "textual>=0.80" --with "httpx>=0.27" --with pytest --with pytest-asyncio -m pytest tests/
```
